# Source routing

## 目录定位

1. 优先使用用户明确路径。
2. 通过当前目录的 `AGENTS.md`、`.git` 或项目标志文件确定仓库根目录，不使用本机绝对路径。
3. 同时识别 `day_01`、`day01`、`day-01`、中文日期目录和无 day 层级的课程目录。
4. 多个学科出现同名 day 时，结合用户上下文、最近修改时间和当前工作目录筛选；仍有多个候选就询问用户。

## 常见目录提示

| 特征 | 可能内容 | 处理重点 |
|---|---|---|
| `day0N_code/`、`第N章*.md` | Python 基础 | 章节理论、晨考、练习代码 |
| `02_code/`、`codeAll/` | NumPy/Pandas | API、广播、索引、数据分析案例 |
| `day0N-笔记/`、`demo*/` | Linux/FastAPI | 概念笔记、逐步 demo、路由与 ORM |
| `01_笔记/`、`上课脚本/`、`04_练习/` | MySQL | SQL 理论、课堂脚本、练习题 |
| `.mmap`、数学笔记 | 机器学习基础 | 公式、概念链、应用场景 |

这些模式只用于辅助归类，不能替代实际文件扫描。

## 文件类型

| 类型 | 读取方式 |
|---|---|
| `.md`、`.txt` | 提取标题、定义、表格、练习和易错点 |
| `.py` | 读取 docstring、概念注释和代表性可运行代码 |
| `.sql` | 提取查询目标、关键语句、预期结果和常见错误 |
| `.ipynb` | 按顺序读取 Markdown 单元和关键代码单元，忽略大体积输出 |
| `.pdf` | 使用可用 PDF 工具提取；扫描件需要 OCR |
| `.docx` | 使用可用 Word 文档工具提取标题、正文和表格 |
| `.mmap` | 运行 `inspect_mmap.py` 重建主题树、绑定最近主题并提取图片；审读纳入范围的知识图片 |
| 图片 | 公式、曲线、表格和文字截图视为正文；装饰图可计数后跳过 |

## 排除项

- `.git/`、`.venv/`、`node_modules/`、`.idea/`、`.obsidian/`、`__pycache__/`
- `.DS_Store`、编译缓存、数据库文件、压缩包中的重复副本
- 已生成的 `*_digest.md`、manifest 和临时文件
- 嵌套 Git 仓库，除非用户明确要求摄入

## 来源优先级

1. 用户自己的当天笔记、作业和提问
2. 当天老师讲义或章节笔记
3. 实际运行过的代码、SQL 和 Notebook
4. 重复课程包和历史副本

先按 SHA256 去重。哈希相同只读一个代表文件；路径不同但内容相同的文件记入 duplicates。

## 累计脑图的进度边界

课程脑图经常把已学和未来章节放在同一文件，不能把整个脑图等同于当天内容。

1. 先列出当天目录的代码、练习和笔记序号。
2. 在脑图中查找这些文件名对应的主题路径，确定最早和最晚命中章节。
3. 当脑图后续章节引用当天目录不存在的更大序号文件时，默认从该处起属于未来课程。
4. 只有脑图有内容、当天目录没有任何进度证据时，才把范围不确定项标为低置信度并向用户说明。
5. 图片沿用旧课件编号时按标题语义归入当前 XML 路径，在来源覆盖中记录编号版本差异。

### `.mmap` 完成条件

- 已读取 `outline.md` 并确认层级，而不是平铺搜索结果。
- 已统计总主题数、图片引用数和纳入范围图片数。
- 已通过图片查看或 OCR 审读纳入范围的知识图片；完全重复图按哈希只读一次。
- 已区分图片承载的新信息与 XML 已有文字。
- 已记录排除章节、装饰图片、损坏资源和未读资源。

## 内容组织

- 按技术问题组织，不按文件顺序堆叠。
- 重复概念只解释一次，后续用关联或复习提示处理。
- 当天再次出现旧概念时可简短复习；不要因“以前总结过”而删除理解当天新内容所必需的上下文。
- 无法验证的结论标注低置信度；明显错误保留原表述并给出 AI 校正。
