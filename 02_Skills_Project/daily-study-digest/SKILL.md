# Daily Study Digest v4

把每日素材压缩成可复述、可实操、可面试表达的复盘笔记。不要把所有源代码和原文机械拼接到 digest。

## 必读资源

- 生成或更新 digest 前，读取 [assets/daily-digest-template.md](assets/daily-digest-template.md)。
- 定位目录、选择文件或处理特殊格式时，读取 [references/source-routing.md](references/source-routing.md)。
- 用 `scripts/build_manifest.py` 建立文件哈希清单，用 `scripts/inspect_mmap.py` 审计脑图，用 `scripts/validate_digest.py` 做最终校验。

## 核心约束

1. 生成“当天完整快照”，不要生成只含新增文件的割裂补丁。
2. 增量只决定哪些 AI 区块需要重算；更新后仍保留完整的当日知识主线。
3. 永远原样保留 `DAILY-DIGEST:USER` 区块。用户填写过的个人总结不得清空、改写或移动。
4. 理论要综合解释，但不得编造。发现源材料错误时，用“原笔记表述 / AI 校正”显式区分。
5. 实操只选 1-3 个代表性案例。单个代码片段尽量不超过 40 行，完整代码链接回源文件。
6. 目标长度为 120-250 行；仅当来源横跨 3 个以上独立模块时才可用 `--max-lines 300` 放宽。超过时优先压缩重复代码和 API 罗列。
7. 使用仓库相对路径，不硬编码本机绝对用户目录。
8. 把 digest 主文档和 AI 总结图写入目标学习目录；存在 `wiki/` 时再创建知识库同步副本，不能只写 `wiki/`。
9. `.mmap` 必须同时读取主题层级和相关内嵌图片；只抽取 XML 文字不算完成读取。
10. 累计课程脑图必须按当天目录中的笔记、代码序号和脑图引用文件名确定进度边界，禁止把未来章节混入当天复盘。

## 工作流

### 1. 确定目标与输出

1. 优先使用用户明确给出的目录或 zip。
2. 用户只说“今天”或 `day_XX` 时，按 source routing 查找候选目录。
3. 多个学科存在同名 day 且上下文不能消歧时，列出候选并请用户选择；禁止静默选择第一个。
4. 先读取仓库根目录的 `AGENTS.md`。
5. 主 digest 写入目标学习目录的 `<学科>-<day>-digest.md`，AI 总结图写入同目录的 `<学科>-<day>-ai总结.png`。
6. 若检测到 `wiki/INDEX.md`，再同步 digest 到 `wiki/daily/<学科>-<day>-digest.md`，manifest 写入 `wiki/state/daily-digest/<学科>-<day>.json`。两份 digest 内容一致，仅资源相对链接可不同。
7. 无知识库时，manifest 默认写入目标目录的 `.<学科>-<day>.manifest.json`。

### 2. 建立增量清单

运行：

```bash
python scripts/build_manifest.py <学习目录> --root <仓库根目录> --previous <旧清单> --output <新清单>
```

- 首次执行时省略 `--previous`。
- 根据 `added / modified / removed / renamed / duplicates` 决定需要重读的源。
- 同名文件内容变化必须重新总结；内容哈希相同的重复文件只读一个代表文件。
- 已存在 digest 且清单无变化时，只运行校验并报告“无源内容变化”，不要重写文件。

### 3. 读取与归纳

1. 先读当天笔记、讲义和题目，建立技术主线；再读代表性代码验证理解。
2. 遇到 `.mmap` 时先运行：

```bash
python scripts/inspect_mmap.py <文件.mmap> --output-dir <临时审计目录> [--include <主题关键词> ...]
```

3. 根据 `outline.md` 重建“根主题 → 章节 → 知识点”层级；不要用关键词平铺代替大纲。
4. 使用可用的图片查看/OCR 工具审读纳入范围的 `images/`：公式、曲线、表格、PPT 截图均属于正文来源。按哈希去重后逐张检查；纯装饰、图标和完全重复图可跳过，但必须计数。
5. 用当天目录中的代码/笔记作为课程进度证据。例如代码止于 `05_...`、脑图后续引用 `07_...` 时，后续章节默认属于未来内容；在“来源与覆盖”列明排除范围。
6. 脑图文字与图片编号不一致时，按主题语义和父子路径对齐，并记录版本差异，不能机械按编号归类。
7. 把晨考、课堂提问和作业合并到对应理论或实操主题，不单独堆放整份内容。
8. 对每个核心主题回答：
   - 这项技术是什么？
   - 它解决什么问题？
   - 为什么采用它？
   - 核心原理是什么？
   - 怎么使用？
   - 与相似方案有什么区别？
   - 常见错误是什么？
9. 对来源不足或无法解析的文件，在“来源与覆盖”中列出，不要猜测其内容。

### 4. 生成固定结构

严格按模板顺序生成：

1. `🧠 今日思维导图`
2. `📚 理论：理解技术`
3. `💻 实操：会使用技术`
4. `📎 来源与覆盖`
5. `🤖 AI 总结`
6. `✍️ 个人总结`

思维导图要求：

- 使用 `flowchart LR`。
- 根节点 → 模块 → 概念，最多 3 层。
- 保持 8-20 个节点，节点文字单行、简短。
- 模块名称必须来自已确认的当天课程大纲；独立代码可作为实操叶节点，但不能取代脑图主线。
- 绘制前逐项核对：每个模块都能指向一个纳入范围的脑图路径或当天源文件；未来章节不得出现。
- 复习内容标为“复习”，当天首次学习内容作为主干；不要把自己的通用机器学习框架冒充课程大纲。
- 放在正文最前，不额外创建重复的“知识图谱”章节。

理论要求：

- 围绕问题、原理、选择理由、对比和易错点组织，不按文件逐份复述。
- API 只保留理解和实操需要的关键项。
- 对不稳定或可疑结论进行校正，并说明依据来自 AI 检查而非原笔记。

实操要求：

- 每个案例包含：场景目标、关键代码、预期结果、步骤解释、常见错误、源文件。
- 保留可运行的最小闭环；不要复制几十个相似练习。
- SQL、Python 等代码块必须标注正确语言。

AI 总结要求：

- 用可用的图像生成工具创建一张竖版知识总结图，不用纯文字 AI 总结代替。
- 图片至少覆盖：今日主线、核心模块、执行流程、关键对比或易错点。
- 使用清晰分区、编号、卡片、箭头和图标；文字少而准确，禁止水印、品牌、二维码和不可读小字。
- 在 `## 🤖 AI 总结` 下只嵌入该图片；不再生成“60 秒面试表达参考”或其他文字小结。
- AI 总结图后立即进入 `✍️ 个人总结`，不在两者之间插入其他章节。

个人总结要求：

- 首次生成时保留空白答题区。
- 使用闭卷复述：当天主线、1-3 个核心技术的“是什么/解决什么/为什么/怎么用”、技术边界、排错、伪代码、知识缺口和下一步验证。
- 要求用户先折叠 AI 总结再回答；AI 不得代填。
- 更新已有 digest 时逐字节保留整个 USER 区块。
- 仅当旧 USER 区块完全空白、用户明确要求升级模板时，才可把旧版空白答题区迁移为新版；已填写内容永不迁移或改写。

来源与覆盖要求：

- 存在 `.mmap` 时必须写“脑图审读”，包含总主题数、总图片数、当天纳入路径、相关图片审读数、跳过数和排除的未来章节。
- 明确区分：完整读取、只做结构检查、缺失依赖、无法运行、未解析或刻意排除。
- 不得把“文件可打开”写成“内容已完整读取”。

### 5. 接入 Obsidian 知识库

检测到 `wiki/INDEX.md` 时：

1. 使用合法 YAML frontmatter：`title`、`type: daily-digest`、`tags`、`related`、`study_date`、`source_dir`、`source_count`、`manifest`、`created`、`updated`。
2. 双链目标必须匹配实际文件名，例如 `[[concept-函数|函数]]`。
3. digest 完成后按仓库 `AGENTS.md` 执行 ingest：更新相关概念页、`wiki/INDEX.md`、`wiki/LOG.md` 和 `wiki/STATE.md`。
4. 在目标目录生成用户明确要求的 digest 与图片属于本 skill 的授权输出；其他源文件仍保持只读。

### 6. 更新已有 digest

1. 更新前把旧 digest 复制到临时目录。
2. 提取并保存 USER 区块。
3. 仅重建 frontmatter 和 AI 区块，再放回完全相同的 USER 区块。
4. 重新生成 AI 总结图时使用新版本文件名，验证完成后再更新 Markdown 引用，避免留下失效图片。
5. 使用旧文件进行保护校验：

```bash
python scripts/validate_digest.py <新digest> --previous-digest <旧digest> --manifest <新清单> --strict
```

6. 校验失败时修复，不交付半成品。

## 质量门槛

最终必须满足：

- YAML 合法且无本机绝对路径。
- Mermaid 存在、使用 `flowchart LR`、节点数合理。
- Mermaid 模块与当天大纲/源文件逐项可追溯，不含未来课程章节。
- 六个章节齐全且顺序正确。
- USER 区块存在；更新时与旧版本完全一致。
- AI 总结区只有一张可访问的本地图片，图后直接进入 USER 区块，不包含“60 秒面试表达”。
- 代码围栏闭合，Markdown 表格中的 `|` 已正确转义。
- 本地源链接存在；manifest 数量与 frontmatter 一致。
- 目标学习目录存在主 digest 和 AI 总结图；有知识库时同步副本也存在。
- 无源变化时保持幂等，不产生重复 digest。
- manifest 含 `.mmap` 时，“来源与覆盖”必须存在脑图审读统计；相关图片未审读不得通过人工质量门槛。

向用户报告目标目录 digest、AI 总结图、wiki 同步副本的路径，以及源文件总数、增删改数量、跳过文件、校验结果和 ingest 状态。
