## 一、LLM 护栏项目

### 1. PurpleLlama / Llama Guard 系列 (Meta)

- **GitHub**: https://github.com/meta-llama/PurpleLlama
- **架构设计**:
  - PurpleLlama 是一个伞形项目，包含多个安全工具和评估基准
  - **Llama Guard 3/4**: 输入/输出审核模型，基于 Llama 3.1/3.2 微调，支持 MLCommons 标准危害分类法，支持 7 种语言、128k 上下文窗口、图像推理
  - **Prompt Guard 2**: 检测提示注入（Prompt Injection）和越狱（Jailbreak）攻击
  - **Code Shield**: 推理时过滤 LLM 生成的不安全代码，防止代码解释器滥用

    - `AgentAlignmentChecks`：监控 AI Agent 推理过程，检测目标错位
    - `CodeShield`：阻止不安全代码生成
- **技术栈**: Python (77.2%), C++ (17.4%), Llama 模型系列
- **核心方法**: 通过微调 Llama 模型进行内容安全分类，在 LLM 输入和输出两端进行过滤。LlamaFirewall 在 AgentDojo 基准测试中将攻击成功率降低超过 90% [1][2]

    - **Retrieval Rails**：RAG 溯源验证
    - **Output Rails**：对 LLM 生成内容进行最终验证
    - **Execution Rails**：工具调用安全检查
  - 使用 **Colang DSL**（领域特定语言）定义安全规则
  - 支持并行编排多个护栏，仅增加约 0.5 秒延迟，检测率提升 1.4 倍
  - 内置基于 NVIDIA Nemotron 模型的 NIM 微服务
- **技术栈**: Python, LangChain/LangGraph/LlamaIndex 集成, GPU 加速 (NIM 微服务), Redis, Hugging Face 模型
- **核心方法**: 可编程策略编排——通过 Colang 规则定义场景策略，同时筛查用户输入和模型输出，支持阻止、筛选或调整后续动作 [3][4]
- **许可证**: Apache 2.0

### 3. Guardrails AI

- **GitHub**: https://github.com/guardrails-ai/guardrails
- **架构设计**:
  - **Guardrails Hub**：预构建验证器（Validators）集合，覆盖 24+ 种风险类型
  - **Input/Output Guards**：拦截 LLM 输入输出，组合多个验证器进行检测
  - **结构化数据生成**：通过 Pydantic 模型 + 函数调用/提示优化从 LLM 生成结构化输出
  - **Guardrails Server**：可作为独立 Flask 服务运行，通过 REST API 交互，支持 OpenAI SDK 兼容接口
- **技术栈**: Python (99.7%), Flask, Pydantic, OpenAI/litellm, Docker + Gunicorn (生产部署)
- **核心方法**: 验证器组合模式——每个 Validator 检测特定风险（如正则匹配、竞品检测、毒性语言检测等），多个 Validator 组合成 Guard，对 LLM I/O 进行拦截验证 [5]
- **许可证**: Apache 2.0

### 4. Slips (Stratosphere Linux IPS)

- **GitHub**: https://github.com/stratosphereips/StratosphereLinuxIPS
- **文档**: https://stratospherelinuxips.readthedocs.io/en/develop/
- **架构设计**:
  - **数据处理流水线**: 输入数据 → 统一格式处理 → 情报富化（IP/MAC/User-Agent/ASN/地理位置等） → 检测模块 → 结果输出

- **核心方法**: 基于 ML 的行为分析，专注检测定向攻击和 C2 命令控制通道，在流级别（而非包级别）进行分析，提供可视化界面 [6]
- **与 SingGuard 的相似性**: 都采用"输入 → 检测引擎 → 输出"的网关式架构，都使用多检测模块协同

### 5. Kitsune

- **GitHub**: https://github.com/yotamhd/Kitsune
- **论文**: Mirsky et al., "Kitsune: An Ensemble of Autoencoders for Online Network Intrusion Detection", NDSS 2018 (arXiv:1802.09089)
- **架构设计**:
  - **AfterImage**: 增量统计特征提取模块，从网络流量中提取时间窗口内的统计特征
  - **KitNET**: 集成自编码器（Ensemble of Autoencoders）神经网络
    - 将特征分组，每组训练一个小型自编码器
    - 各自编码器的重构误差再输入到一个上层自编码器
    - 最终输出异常分数
- **技术栈**: Python, NumPy, 神经网络（自编码器）
- **核心方法**: 无监督异常检测——仅用正常流量训练，运行时通过自编码器重构误差检测异常流量模式，适合在线实时检测 [7]
- **与 SingGuard 的相似性**: 都使用 ML 模型进行实时安全检测；Kitsune 的集成自编码器思路与 SingGuard 的双模型架构有类似的多层检测理念

# GitHub 上结合 AI/ML 做网络流量安全检测的代表性开源项目

## 一、用大模型/机器学习模型检测网络流量的项目

### 1. Kitsune-py
- **GitHub**: https://github.com/ymirsky/Kitsune-py
- **论文**: NDSS 2018, "Kitsune: An Ensemble of Autoencoders for Online Network Intrusion Detection"
- **架构设计**: 三层流水线架构:
  1. **AfterImage 特征提取层** — 用阻尼增量统计(damped incremental statistics)高效追踪每个网络通道的模式,为每个数据包提取特征向量,捕获该包所在通道和发送方的时序上下文
  2. **KitNET 集成层** — 将特征映射到一组小型自编码器(autoencoder)的可见神经元,每个自编码器尝试重建实例特征并计算 RMSE 重建误差
  3. **输出自编码器投票层** — 将各 RMSE 转发到一个输出自编码器,作为非线性投票机制汇总异常分数
- **技术栈**: Python 64.8%, Cython 35.2%; 依赖 scapy(或 tshark/Wireshark)解析 pcap; Anaconda 环境
- **核心思路**: 无监督、在线、轻量的网络入侵检测。不需要标注数据,只需用正常流量训练;内存中同一时间只存一个实例;参数 m(单个自编码器最大输入数)可调节速度与精度权衡。适用于资源受限的网关/路由器设备
- **特点**: 即插即用、增量学习、实时逐包检测

### 2. ET-BERT
- **GitHub**: https://github.com/linwhitehat/ET-BERT
- **论文**: WWW 2022, "ET-BERT: A Contextualized Datagram Representation with Pre-training Transformers for Encrypted Traffic Classification"
- **架构设计**: 两阶段 BERT 范式:
  1. **预训练阶段** — 在大规模无标签加密流量上,利用多层注意力机制学习数据报间上下文关系(inter-datagram contextual)和流量传输间关系(inter-traffic transport);构建加密流量语料库,训练专用词表
  2. **微调阶段** — 在小规模有标签加密流量上微调,执行包级(packet-level)分类任务(如 TLS 1.3 应用识别、恶意软件检测等)
- **技术栈**: Python; PyTorch (torch >= 1.1); 基于 UER-py 框架; scapy/tshark/SplitCap 做流量预处理; CUDA 11.4 + Tesla V100S; WordPiece 分词; 可选 pytorch-crf 做序列标注
- **核心思路**: 将 BERT 预训练范式从 NLP 迁移到加密流量领域。直接从加密数据报的原始字节中学习上下文表征,不依赖明文内容,可识别 VPN/Tor 等加密流量类型。在 CSTNET-TLS 1.3 等数据集上达到高准确率
- **特点**: 迁移学习能力强,预训练一次后可微调适配多种加密流量分类场景

### 3. Slips (StratosphereLinuxIPS)
- **GitHub**: https://github.com/stratosphereips/StratosphereLinuxIPS (v1.1.21, 2026年6月更新)
- **创建者**: Sebastian Garcia, 捷克布拉格捷克理工大学 Stratosphere 实验室 (2012年)
- **架构设计**: 高度模块化的 Python 系统:
  - **流量采集**: 依赖 Zeek 网络分析框架捕获实时流量和解析 PCAP;也支持 Suricata、Argus 的 flow 数据
  - **进程间通信**: Redis (>= 7.0.4) 作为消息总线连接各模块
  - **检测模块**: 多个独立模块并行运行,包括 ML 模型检测、威胁情报(40+ feeds)、专家启发式规则、HTTPS 异常检测、P2P IoC 共享等
  - **证据积累机制**: 收集恶意行为证据,使用训练好的阈值在证据足够时触发告警
  - **联邦学习**: 通过 feel_project 子模块支持
- **技术栈**: Python 90.5%; Zeek 1.7%; TensorFlow (pinned 2.19.1); Redis; Docker 部署; Web 界面(Flask); 支持 Linux/MacOS/Windows(Docker)
- **核心思路**: 首个免费的行为机器学习 IDS/IPS。基于时间窗口(time-window)对网络流量做行为分析,重点检测定向攻击和 C2 通道。融合 ML 模型 + 威胁情报 + 启发式规则三重检测,以证据积累替代单一阈值告警
- **特点**: 模块化、可扩展(支持自定义检测模块)、Docker 一键部署、P2P 节点共享 IoC、在 BlackHat 多次展示

### 4. TrafficLLM
- **GitHub**: https://github.com/ZGC-LLM-Safety/TrafficLLM
- **论文**: "TrafficLLM: Enhancing Large Language Models for Network Traffic Analysis with Generic Traffic Representation"
- **架构设计**: 三个核心模块:
  1. **流量域分词(Traffic-Domain Tokenization)** — 在大规模流量语料上训练专用分词器,扩展 LLM 原生 tokenizer,缓解自然语言与异构流量数据的模态差异,减少 token 长度提高效率
  2. **双阶段微调管道(Dual-Stage Tuning Pipeline)** — 第一阶段训练 LLM 理解专家指令文本,第二阶段学习任务相关流量模式,实现跨不同任务的通用表征学习
  3. **EA-PEFT 可扩展自适应** — 将不同流量表示能力拆分为不同 PEFT 模型,新增网络环境时只需训练轻量模块,无需重新训练整个模型
- **技术栈**: 基于 Llama2-7B; PEFT/LoRA 参数高效微调; 自定义流量域 tokenizer; 约 0.4M 样本的调优数据集(指令文本+流量数据)
- **核心思路**: 将 LLM 的泛化能力引入网络流量分析。构建第一个大规模流量域 LLM 自适应数据集,支持 10 种下游任务(恶意软件检测、加密应用分类、Web 攻击检测、僵尸网络检测等)、229 种流量类型。F1 达 0.9875(检测)和 0.9483(生成),比现有方法提升 80.12% 和 33.92%,对未见流量泛化性提升 18.6%
- **特点**: 兼具流量检测和流量生成(红队模拟)能力;支持对话式交互,降低安全人员操作门槛;可集成到 NTA/SIEM 系统中

## 三、类似 SingGuard 的 AI 安全网关项目

### 6. SingGuard / SingGuard-NSFA
- **开源方**: 蚂蚁集团 AI 安全实验室 (2026年7月13日开源)
- **模型下载**: 模型刚开源,具体 HuggingFace/ModelScope 链接需关注蚂蚁 AI 安全实验室官方渠道(参考蚂蚁此前模型惯例,预计在 HuggingFace 和 ModelScope 同步发布)
- **架构设计**: 双模型体系:
  - **SingGuard(多模态安全护栏)** — 面向文本、图片及跨模态内容的统一安全判断框架;采用"快慢结合"推理模式(先快速初判,复杂场景再启动深度推理);支持运行时动态加载自然语言安全规则,无需重训即可更新规则
  - **SingGuard-NSFA(智能体行为安全护栏)** — 基于 CIA 三元组(保密性/完整性/可用性)+ OWASP 指南,将风险分为 7 大类、28 中类、185 个具体场景;提供两种工作模式:详细风险分析报告模式(事后审查)和 50ms 实时判定模式(线上拦截);支持"热插拔式风险扩展",新增风险类型只需训练轻量模块
  - **四种模型规模**: 0.8B(端侧/嵌入式)、2B、4B、9B(云端生产环境)
- **技术栈**: LLM 安全模型; 训练数据超 10 万条样本; 支持 133 种语言; 0.8B 模型即可达到 8B 性能
- **核心思路**: 从"内容安全"范式转向"行为安全"范式。SingGuard-NSFA 不是内容过滤模型,而是行为安全护栏 — 在智能体执行动作(如 `rm -rf`、调用 API)之前完成 50ms 实时安全检测。SingGuard 在 35 个数据集上 F1 平均最高,优于 Llama Guard 3、Google ShieldGemma、GPT-5.1、Gemini 3-Pro
- **生态**: 与 OpenClaw 安全审计 + ClawAegis 防御插件(清华联合开源) + ASL 智能体可信互连协议 形成全链路开源安全栈
- **特点**: 行为安全(非内容安全)、CIA+OWASP 分类体系、50ms 级实时拦截、多规模部署、多语言覆盖

### 7. Portkey AI Gateway
- **GitHub**: https://github.com/Portkey-AI/gateway (MIT License, 8k+ stars)
