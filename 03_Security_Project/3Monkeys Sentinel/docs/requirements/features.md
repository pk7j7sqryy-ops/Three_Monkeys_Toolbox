## 一、项目概述

3Monkeys Sentinel 是一款 AI 驱动的本地网络安全 Agent，通过双层检测架构（规则引擎快筛 + Agent 自主调查）实现实时流量检测、智能分析与主动响应。核心差异化是「Agent 推理链路可视化」——不仅告诉用户「发生了什么」，还展示「AI 是怎么思考的」。

### 版本范围定义

| 模块 | 版本 | 说明 |
|------|------|------|
| 流量采集 | 最小版 | Scapy 抓包 + 基础协议解析 + 特征提取 |
| 规则引擎 | 最小版 | 5 条核心规则 + 正则匹配 + 威胁情报本地缓存 |
| **Agent 核心** | **完整版** | 推理循环 + 摘要节点 + 上下文压缩 L1-L5 + 并发队列 + 优先级调度 + 去重合并 |
| 工具集 | 完整版 | 14 个工具全实现（Agent 核心需要） |
| **记忆系统** | **完整版** | 短期 State + SQLite 长期 IP 画像 + ChromaDB 向量记忆 + EWMA 衰减 + 相似事件检索 |
| 前端 | 最小版 | 告警列表 + Agent Trace 两个页面 |
| **模型 Pipeline** | **完整版** | 自动标注 + 数据增强 + LoRA 微调 + Q4 量化 + 三组评估 + 训练数据集 500 条 |
| 模型运行策略 | 最小版 | 本地 Ollama 默认 + 统一 Provider；Kimi K3 不本地部署、不阻塞 MVP |
| 测试 | 最小版 | 5 场景评估 + Mock 工具测试 |
| 运维 | 最小版 | Tauri .dmg 打包 |
| 安全防护 | 最小版 | system prompt 加固 + payload 转义 |
| 攻击场景 | 最小版 | 5 场景（C2/SQLi/扫描/XSS/正常） |

## 三、攻击场景矩阵

> 🟢 = 最小版演示场景 | ⚪ = 暂不实现

| 攻击类型 | 典型特征 | 规则引擎处理 | Agent 预期推理路径 | 预期响应 | 版本 |
|---------|---------|-------------|-------------------|---------|------|
| SQL 注入 | HTTP GET/POST 包含 `UNION SELECT`、`OR 1=1` 等 | 规则直接命中，快速告警 | 无需进入 Agent（或仅确认） | 告警 + 记录 | 🟢 |
| XSS | HTTP 请求包含 `<script>`、`javascript:` 等 | 规则直接命中，快速告警 | 无需进入 Agent（或仅确认） | 告警 + 记录 | 🟢 |
| 端口扫描 | 同一源 IP 短时间内访问 >10 个不同端口 | 规则命中（扫描模式） | 查威胁情报 → 查历史 → 若恶意则封禁 | 记录 + 通知 | 🟢 |
| C2 回连 | 规律性连接可疑 IP（如每 60 秒一次） | 规则未命中，送入 Agent | 查威胁情报（Tor/恶意）→ 查历史连接 → 查 DNS → 判定 C2 → 封禁 | 封禁 IP + 通知 + 报告 | 🟢 |
| 正常流量 | 正常 HTTPS/DNS 通信 | 规则不命中，不送 Agent | 无 | 无告警 | 🟢 |
| 命令注入 | HTTP 请求包含 `; rm -rf`、`| whoami` 等 | 规则直接命中，快速告警 | 无需进入 Agent（或仅确认） | 告警 + 记录 | ⚪ |
| DNS 隧道 | DNS 请求异常（大负载、高频、非常规域名） | 部分命中（高频检测） | 分析 DNS 模式 → 查域名信誉 → 封禁域名 | 封禁域名 + 通知 | ⚪ |
| 数据外泄 | 大量数据流向外部可疑 IP | 规则未命中，送入 Agent | 查历史流量基线 → 判断是否异常 → 告警 | 通知 + 报告 | ⚪ |
| 暴力破解 | 同一 IP 高频尝试登录 | 规则命中（频率检测） | 查历史 → 确认攻击 → 封禁 IP | 封禁 IP + 通知 | ⚪ |

## 四、非功能需求

| 类别 | 需求 | 目标值 |
|------|------|--------|
| **性能** | 规则引擎处理延迟 | < 1ms / 包 |
| **性能** | Agent 单事件处理延迟 | 500ms ~ 3000ms |
| **性能** | 前端告警推送延迟 | < 100ms |
| **资源** | 内存占用（含 Ollama 7B） | < 4GB |
| **资源** | CPU 占用（空闲时） | < 5% |
| **资源** | CPU 占用（Agent 调查时） | < 30% |
| **隐私** | 流量数据外传 | 默认禁止；可选远程调查仅发送用户确认后的脱敏事件摘要 |
| **隐私** | 威胁情报查询 | 仅查询 IP/域名，不发送 payload |
| **稳定性** | 连续运行无崩溃 | > 72 小时 |
| **稳定性** | Agent 循环异常退出 | 单事件失败不影响后续检测 |
| **可维护** | 代码测试覆盖率 | 核心模块 > 60% |
| **可维护** | 日志记录 | 全链路结构化日志 |

## 五、优先级定义

- **P0（Must have）**：MVP 必须功能，缺少则核心流程无法跑通。包括：抓包、规则引擎、Agent 推理循环、基础工具、前端告警/Trace、系统通知。
- **P1（Should have）**：完整产品体验所需，面试展示有说服力。包括：记忆系统、响应策略分级、规则管理、Dashboard、PCAP 回放、模型微调。
- **P2（Nice to have）**：增强体验，时间充裕时做。包括：开机自启、后台托盘、主机隔离、SSL 查询。
